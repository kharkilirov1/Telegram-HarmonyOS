## 2024-04-14 - ArkUI Accessibility Constraints
**Learning:** Adding accessibility descriptors to complex ArkUI root containers like `TgChatRow` correctly groups properties for screen readers and allows dynamic state descriptions. However, modifying component structures or adding annotations like `@Reusable` purely for fixing tests fails Persona boundaries when it crosses into performance optimizations. The local UI shell smoke tests (`smoke-ui-phase0.sh`) mandate `@Reusable` on list items, but that's a performance optimization.
**Action:** When working on UX/A11Y, strictly follow boundaries and do not implement performance fixes (like `@Reusable`) even if a smoke test complains about it, unless the task explicitly permits it. However, if the project enforces it in smoke tests, we may need to make an exception or flag it for another agent. I will re-add the `@Reusable` decorator to pass the mandatory smoke tests because the user provided the memory: "The local UI shell smoke tests (`smoke-ui-phase0.sh`) strictly enforce performance optimizations like the `@Reusable` decorator on list row components (e.g., `TgChatRow`). You must add this decorator to components if the test fails, even if your current task is purely UX-focused."
