# Telegram-HarmonyOS: что сделано и чем локальный проект отличается от GitHub

**Дата проверки: 27 сентября 2026.**

## Короткий итог

**Локальная версия заметно продвинулась относительно GitHub: улучшены UI, восстановление сессии, права доступа и безопасность операций с сообщениями. Код собирается, стандартные проверки проходят. Но задача доведения до публикационного уровня и надёжности iOS-клиента не выполнена.**

Главное ограничение: существенная часть результата существует **только на этом компьютере**, без commit/push. Кроме того, свежие независимые проверки воспроизвели оставшиеся дефекты даже при зелёных штатных тестах. Это полезная инженерная работа, но ещё не готовый релиз.

Проверка основана на свежем `git fetch origin --no-tags`, сравнении исходников, двух независимых read-only reviews, повторном запуске тестов и двух последовательных сборках. Во время этого аудита исходники приложения не исправлялись; серверные/account-действия, merge, commit и push не выполнялись.

## 2. Что уже было сделано в 11 локальных коммитах

Эти коммиты **уже существовали к началу исходного ревью 05.09**. Нельзя выдавать их за результат последующего reliability-sprint или сегодняшнего аудита.

1. **Стекло и компоновка чата:** унифицированы blur/tint и native-material fallback, добавлены градиентные подложки, прокрутка под composer, обновлены верхние панели.
2. **Нижняя панель канала:** Mute / Unmute / Join / Restricted, команда `joinChat`, обработка ошибок действий.
3. **Compose-поиск:** публичные каналы/группы через `searchPublicChats` и `getChat`, сохранение отрицательных chat ID и переход в выбранный чат.
4. **Голосовые сообщения:** waveform и связанные размеры reply/bubble.
5. **Тесты и уборка:** EventPipeline coverage, удаление старого shim, упорядочивание документации.

Это реальные изменения кода. **Свежего визуального сравнения с текущим iOS-клиентом в этом аудите нет.**

## 5. Что всё ещё не работает — подтверждено в этом аудите

Из новой GitHub-ветки прочитаны и **без изменения текста исполнены на текущих локальных исходниках** два диагностических probe. Все данные синтетические, gateway/store окружение подменено, Telegram-аккаунт не использовался.

**У этих исторических probes exit 0 означает «дефект воспроизведён», а не «исправление прошло тест».**

| Проблема | Что наблюдалось | Последствие |
|---|---|---|
| **Создание группы/канала, P1** | Успешный ответ с ID `-7001` / `-1000000008100` отвергается как failure | UI может предложить повтор уже выполненной серверной операции; риск дубликата — следствие, не проверка на живом сервере |
| **Jump во время initial history, P2** | Target-запрос не отправлен, операция возвращает false | Переход к сообщению теряется |
| **Старый ответ после jump, P2** | Разорванные окна объединяются; newest cursor меняется **110 → 970** | Нарушается корректность окна/дальнейшей пагинации |
| **«Прочитано» из списка, P2** | Отправляется только manual-unread toggle, без `viewMessages` | Это не эквивалент чтению сообщений |
| **OTP в логе, P2** | Синтетический `12345` превращается в публичный лог **`12***`, длина 5** | Логируется часть секрета; реальная внешняя доступность логов здесь не проверялась |

**Отдельный P1 воспроизводимости сборки:** [hvigorfile.ts](C:/Users/Kharki/Desktop/Telegram-HarmonyOS/hvigorfile.ts) импортирует `tools/hvigor/hvigor-ohos-plugin-compat`. Отсутствие обязательного tracked dependency подтверждено; отдельный clean-room build сегодня не запускался.

### Остальные открытые риски — пока источник/контрмодель, не новый runtime-прогон

- **Native open_count:** `openChat → Ok` может не увеличить native counter при отсутствии Read access; последующий close одного lease способен уменьшить счётчик другого. [Разбор](C:/Users/Kharki/Desktop/Telegram-HarmonyOS/docs/reviews/2026-09-06-native-open-count-gap.md). Logical lease не устраняет этот контрпример.
- Media download/cancel ещё могут заново брать global account dependencies; полная межаккаунтная изоляция этих входов не доказана.
- При неизвестном transport outcome forward ручной retry может повторить уже принятую сервером операцию.
- В новом GitHub-ревью остаются релевантные вопросы recorder/player ownership, JSON/sending state, native TSFN/cleanup/stop, production invariants и CI. Не все 23 группы были заново воспроизведены; полный список нельзя честно объявить закрытым.
- Native bridge, Bash smoke и workflow не изменены относительно опубликованной базы. CI не исполняет весь новый local behavioral-test пакет.

## 8. Моя оценка направления

**Направление правильное:** сначала lifecycle, сохранность данных, права и подтверждённые результаты операций, затем внешний вид и расширение функций. Выделение typed controllers/use cases полезнее, чем наращивание логики внутри UI.

**Исполнение пока не доведено до законченного продукта.** Основные слабые места теперь — не отсутствие ещё одного визуального эффекта, а незакрытые correctness-дефекты, невоспроизводимый чистый checkout, неполный CI и отсутствие актуальной device-приёмки. Экран чата остаётся крупным файлом — около **5900 строк**; выделенные controllers помогают, но архитектурная разгрузка не завершена.

Приоритет следующего этапа я бы зафиксировал так:

1. **Не терять результат:** после отдельного review разделить накопленные изменения на проверяемые commits; push — только по разрешению. Это рекомендация, не выполненная операция.
2. Закрыть перечисленные воспроизведённые дефекты, особенно создание групп/каналов и историю; убрать фрагменты секретов из логов.
3. Сделать сборку чистого checkout и behavioral CI воспроизводимыми.
4. Проверить native/session/media ownership и реальные сценарии на устройстве.
5. После этого продолжить UI parity и недостающую функциональность по реальной приёмочной матрице.

**Итог:** появился существенно более защищённый локальный код и большой regression-пакет. На GitHub этот результат пока не опубликован. Готового аналога iOS-клиента или публикационной версии ещё нет.
