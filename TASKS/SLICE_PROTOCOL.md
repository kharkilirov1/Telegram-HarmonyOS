# SLICE_PROTOCOL — инженерный цикл одного среза

Обязателен для любой работы: UI-атом, рантайм-срез, фича, дефект. Цель — чтобы агент работал как
инженер: сначала посмотрел список и код, потом сделал карту, потом реализовал с тщательной сверкой
с iOS-эталоном, без «пока быстро, потом доведём».

Связанные документы:

| Документ | Роль |
|---|---|
| `TASKS/CAPABILITY_MATRIX.md` | **что вообще бывает** и в каком состоянии (статус + доказательство) |
| `TASKS/WORKMAP.md` | что делаем **сейчас** (1–3 пункта, перегенерируется каждый цикл) |
| `TASKS/TODO.md` | долгоживущая очередь и гейты |
| `TASKS/SLICE_TEMPLATE.md` | шаблон плана среза (копируется в отчёт/работу) |
| `TASKS/PRODUCTION_PARITY_PLAN.md` | критерии «готово» по фазам |
| `TASKS/AGENT_EXECUTION_PLAN.md` | порядок фаз |

---

## 0. Что считается срезом

Один срез = **одна пользовательская возможность** или **один узкий дефект**, который можно
проверить независимо. Не «экран целиком», не «сразу 5 фич», не «рефакторинг + фича».

Если работа не помещается в один срез — это несколько срезов в `WORKMAP.md`, а не один большой.

---

## 1. Preflight (обязателен, без него не начинать)

1. `STATUS.md`, `TASKS/TODO.md`, `TASKS/WORKMAP.md`, релевантные `TASKS/LESSONS.md`.
2. Строка в `TASKS/CAPABILITY_MATRIX.md`: её статус, `code evidence`, `related`, `seam`.
   Строка со статусом `unverified` — сначала верифицируется, потом работа.
3. iOS-референс: путь в `C:\Refs\Telegram\Telegram-iOS-current` + актуальный скриншот/видео для
   нужного состояния. Android/Nekogram — только как fallback при неоднозначности.
4. Для ArkTS/ArkUI/API — запрос в `harmonyos_docs` (обязательно, не из памяти).
5. Для сетевого поведения — точная форма метода из `tdlib/td/generate/scheme/td_api.tl`.

---

## 2. Разбор референса (результат обязателен)

**UI-срез** → паспорт `entry/src/main/ets/ui/tg_ui/spec/<Atom>.md`:
входы (поля модели), матрица состояний, контракты выравнивания, слойность/фон/эффекты, маппинг в
токены, iOS-пути и id скриншотов, «что делаем нативно и почему».

**Рантайм-срез** → slice-документ (в `docs/reviews/` как датированный отчёт или отдельный файл):
методы TDLib, владелец состояния, guard'ы (route/account/lifecycle/input revision), отмена, поздние
колбэки, коды ошибок, что считается успехом.

Фраза «в iOS примерно так» без пути к файлу/скриншоту — не разбор.

---

## 3. Швы и задел на связанные фичи

1. Возьми из матрицы колонку `related` — это фичи, которые придут в этот же экран/стрим/контракт.
2. **Назови шов**: интерфейс, параметр, поле стейта, событие, токен, место в recovery-пути —
   через который соседняя фича встанет без переделки.
3. **Не строй спекулятивные абстракции.** Запрещено: универсальные слои «на будущее», интерфейсы
   без текущего потребителя, конфиги без владельца, «оставим место под X» без записи в матрице.
4. Всё, что ты сознательно решил **не** трогать, но что может помешать соседям, — запиши в план
   среза как risk/decision.

Задел = не код «на вырост», а **не закрытая дверь**.

---

## 4. Контракт и тест до реализации

- Для UI: состояния и их источник (селектор/VO), что живёт в VO для LazyForEach-строк.
- Для рантайма: типизированные доступы TDLib (`TdObject`-accessor), без plain-record кастов;
  владелец операции и его cleanup; отмена и повторный вход.
- Сначала **focused RED** (host-тест `scripts/test-*.cjs`, `entry/src/ohosTest/ets/test/*.test.ets`)
  или named runtime witness, который сейчас падает/не подтверждён. Потом реализация.

---

## 5. Реализация

- Tokens-first (`TgUiTokens.ets`), без магических чисел в виджетах.
- V2-декораторы для `tg_ui`; V1/V2 не смешивать.
- Legacy не ломать: старый путь остаётся рабочим до приёмки нового.
- Одно узкое изменение на компоновку; без попутных рефакторингов «по пути».
- **Никаких** `TODO/FIXME` в коде и «временных» заглушек. Нельзя — см. §8.

## 6. Проверка (всё применимое, не выбор одного)

| Гейт | Команда |
|---|---|
| Сборка | `powershell -ExecutionPolicy Bypass -File .\scripts\smoke-build.ps1` |
| UI-контракт | `powershell -ExecutionPolicy Bypass -File .\scripts\smoke-ui-phase0.ps1` и `bash ./scripts/smoke-ui-phase0.sh` |
| Host-тесты | `node scripts/run-host-tests.cjs` (или точечный `scripts/test-*.cjs`) |
| On-device тесты | `entry@ohosTest` в DevEco |
| Runtime | эмулятор/устройство: свежий процесс, скриншоты в одинаковых состояниях |
| ссылки/числа в доках | проверка относительных ссылок и заявленных счётчиков |

## 7. Сверка с iOS (обязательна для пользовательской функции)

Side-by-side: iOS-скриншот состояния ↔ наш скриншот того же состояния. Для каждого расхождения:

- **баг** — исправить в этом срезе;
- **платформенное ограничение** — записать в паспорт/отчёт с причиной и ссылкой на доки;
- «похоже», «примерно», «потом подправим» — запрещено.

Кроме пикселей сверяется **поведение**: одинаковые действия дают одинаковый результат (включая
ошибочные сценарии).

---

## 8. Definition of Done (все пункты, иначе срез не закрыт)

- [ ] строка `CAPABILITY_MATRIX` обновлена: статус, `code evidence` (файл:строка), `witness` (дата)
- [ ] состояния: empty / loading / error / удалённый контент / длинные строки / emoji-RTL
- [ ] light + dark, масштаб шрифта, safe area/keyboard
- [ ] жизненный цикл: вход-выход-повторный вход, поздние колбэки, отмена, нет утечек подписок
- [ ] ошибки TDLib обработаны по коду; деградация объяснена (не тихий фейл)
- [ ] нет временных решений и мёртвых концов; нет disabled-контрола без объяснения
- [ ] gates из §6 зелёные; witness приложен
- [ ] `STATUS.md` / `TASKS/TODO.md` / `TASKS/LESSONS.md` обновлены; нетривиальный срез — датированный отчёт в `docs/reviews/`

---

## 9. Реестр долга — единственный легальный способ оставить недоделанное

Иногда срез упирается в блокер. Тогда:

1. Добавь строку в `TASKS/TODO.md`, раздел **Debt**: что не сделано, почему не сейчас, кто владелец,
   триггер возврата (какое событие/фича заставит вернуться), видимое пользователю последствие.
2. Строка матрицы остаётся `partial` — она не закрывается.
3. Долг **запрещён**, если он даёт: мёртвую кнопку/тихий фейл, потерю данных, проблему
   безопасности, порчу состояния, регресс уже принятого. Такое чинится в этом же срезе.

Долг без владельца и триггера — не долг, а забытый баг. Так нельзя.

---

## 10. Проверка корректности (не только «собирается»)

Перед закрытием среза ответить на:

- **Логика vs эталон:** таблица «действие → поведение iOS → наше поведение»; расхождения разобраны.
- **Ошибочные пути:** что при timeout / rejected / late ack / повторном тапе / двойной отправке.
- **Владение:** кто освобождает ресурс, что при отмене и при выходе из экрана.
- **Данные:** пустой список, отсутствующее поле, огромные значения, null/undefined от TDLib.
- **Производительность:** не добавляем ли O(n²), не держим ли тяжёлый объект в стейте экрана.
- **Доступность:** tap targets, шрифтовое масштабирование, чтение скринридером (где применимо).

---

## 11. Когда нельзя объявлять «готово»

- матрица всё ещё `unverified` или без witness;
- есть незаписанный долг;
- скриншот не сверен с iOS;
- gates красные или «проверю потом»;
- поведение отличается от эталона и это не задокументированное ограничение платформы.

---

## 12. Формат отчёта после среза

Что сделано → какие файлы → чем верифицировано (команды + witness) → какие состояния покрыты →
что осталось (долг, если есть) → какой следующий срез из `WORKMAP`.
